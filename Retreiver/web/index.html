Open metric glossary and term explanations
Score

Weighted winner score used for ranking: Recall@5, MRR, nDCG@5, and a small latency component.

Recall@K / R@K

Whether at least one relevant chunk appears within the top K retrieved results. R@5 uses the top 5.

MRR

Mean Reciprocal Rank. Measures how early the first relevant result appears. Rank 1 scores 1.0, rank 2 scores 0.5.

nDCG@5

Normalized Discounted Cumulative Gain at 5. Rewards relevant chunks in the top 5, with higher ranks worth more.

P@5

Precision at 5. Share of the top 5 retrieved chunks that are relevant.

Avg rank

Average rank position of the first relevant chunk, calculated only when a hit exists.

No hit

Number of evaluated queries where no relevant chunk was found in the retrieval window.

Avg sec/query

Average retrieval latency per query for that one pipeline configuration. It is not the total time for all 500 rows. If the table says 120 queries, this value is averaged across those 120 query runs.

Chunker

The document splitting method used before embedding, for example heading sections or fixed-token chunks.

Embedding

The model that converts each text chunk and query into vectors for similarity search.

Vector DB

The vector store used to store and search vectors, currently Qdrant, PGVector, Weaviate, and FAISS.

Reranker

Second-stage model that reorders retrieved chunks after vector search to improve relevance.

Ground truth

The reference evaluation set used to decide whether retrieved chunks match the expected answer/evidence.
