# WNS one-click VM benchmark package

This package contains everything needed for the VM-hosted benchmark setup.

## One command on VM

From this package root on the Linux VM:

```bash
bash setup_all_on_vm.sh --host <VM_HOST_OR_IP>
```

If you do not know the IP, run without `--host`; the script will auto-detect the first non-loopback IP:

```bash
bash setup_all_on_vm.sh
```

If model downloads are slow and you only want infrastructure first:

```bash
bash setup_all_on_vm.sh --skip-model-smoke
```

## What the script does

- Uses only VM-facing ports `5000-5010`.
- Starts Jina/GTE FastAPI embedding service on `5000`.
- Starts Qdrant on `5001` and Qdrant gRPC on `5002`.
- Starts PGVector/Postgres on `5003`.
- Starts Weaviate on `5004`.
- Installs real benchmark adapters into `Retreiver`.
- Writes `Retreiver/.env` with VM endpoints.
- Writes Windows CMD helper scripts so the local dashboard can connect to VM ports.
- Runs syntax, config, and service checks.

## Local frontend connection

After VM setup, on the local machine from the `Retreiver` root:

```cmd
scripts\windows\Connect-Frontend-To-VM.cmd <VM_HOST_OR_IP>
```

This one local command writes `.env`, tests the VM endpoints, and starts the dashboard.

Manual fallback:

```cmd
scripts\windows\Configure-LocalFrontendForVM.cmd <VM_HOST_OR_IP>
scripts\windows\Start-WnsDashboard-VM.cmd
```

If you run the helper file that was generated by the VM script, it already has the detected VM IP as its default.

Dashboard URL:

```text
http://127.0.0.1:8765
```

The local dashboard backend will load `.env` and call the VM endpoints:

```text
http://VM_HOST:5000/embed/jina
http://VM_HOST:5000/embed/gte
http://VM_HOST:5001
postgresql://wns:wns_password@VM_HOST:5003/wns_benchmark
http://VM_HOST:5004
```

## Notes

A VM script cannot directly modify a separate local work machine. So the VM script generates the exact local CMD helper and `.env` settings needed. Run the local helper once from `Retreiver` before opening the dashboard.
